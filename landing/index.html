01

What it does

A tiny browser-plus-installer for GitHub release assets. Seven things, done well.

Live release feed

Pulls the latest assets straight from a GitHub repo, so the list is never stale. Add as many repos as you like — the default one is built in.

Digest check

Every download is hashed and compared against the published digest before it touches the installer.

Installs for you

Downloads, verifies, then opens the system installer. Per-repo view keeps arm64 + universal APKs; All Apps keeps everything.

Search

Filter the list by name as it loads. Icons fetch lazily, so a slow network never stalls the page.

History

Remembers what you downloaded — name + digest — in a small local database. Handy for spotting whether two builds actually differ.

Heads-up

Subscribes to an ntfy topic and pings you when a matching build shows up. Optional, host configurable.

Material You

Follows your wallpaper colours, falls back to a seed colour, and respects dark mode.

02

How you use it

Three taps and you're done. The intro screen walks through permissions.

  1. Install the APK

    Grant notifications, storage and install unknown apps when asked. Takes about a minute.

  2. Pick a repo

    Use the built-in default, add your own user/repo, or open the All Apps drawer to browse everything at once.

  3. Tap → verify → install

    Watch the progress dialog do its thing, then confirm in the system installer. Done.

04

Questions

The honest answers, up front.

Does it patch anything?

No. It downloads builds somebody already published as GitHub release assets. If what you want isn't in a release, this app can't make it.

Where do the APKs come from?

Wherever you point it. The default is configured at build time; add any GitHub user + repo in the repo manager and remove them again whenever.

Why care about the digest check?

It doesn't make an APK more trustworthy than its source. It just catches a truncated download or mismatched file before you install it — the cheap kind of paranoia.

Which devices?

Release builds target android-arm64 — basically every phone from the last several years. Debug builds from CI can be whatever you compile.

Something crashed.

The app reports crashes through Sentry. Filing an issue on GitHub with your device model + what you were doing is the fastest fix.

Is this official?

No. Unofficial and unaffiliated with the ReVanced project. It just talks to GitHub releases like a browser would.
